# 0010 - Evaluation history as append-only JSON Lines, with a static Markdown trend report

**Status:** Proposed (P5; needs human approval)

## Context
`eval/run_eval.py` overwrites `eval/results/results.json` and `RESULTS.md` on every run, so there is no record of
earlier runs. P5 asks for every run to be appended to a history file, stored with commit, prompt versions and
models (P5-AC2), and for a trend report that lists at least the last 10 runs per metric, regenerated by one command
(P5-AC3). SPEC-GAP-006 defaults to a static Markdown report in `eval/results/` with no hosted service.
Options considered: a SQLite table (`src/state.py` holds caches that may be wiped, and binary files diff badly in
git), one JSON file rewritten each time (not append-only; a crash mid-write can lose history), JSON Lines.

## Decision
- `eval/results/history.jsonl`, one JSON object per run, **append-only**: the writer opens the file in append mode
  and never rewrites earlier lines. It is committed to git, together with the phase.
- Each line holds `schema`, `run_at`, `commit`, `commit_dirty`, `suite`, `answer_model`, `checker_model`,
  `prompt_versions`, `settings`, `datasets` (SHA-256 of the question sets used) and a flat `metrics` map of dotted
  metric names to numbers (or `null`). The full shape is the `HistoryEntry` TypedDict in `docs/phases/p5-plan.md`.
- `python -m eval.trend` (`make eval-trend`) reads the history and writes `eval/results/TRENDS.md`: one table per
  metric with that metric's last 10 runs (default). The output depends only on the history file (no "generated at"
  time), so regenerating it without new runs changes nothing. `run_eval` also regenerates it after each run.
- No new dependency and no hosted service.

## Consequences
- History is easy to diff and review in pull requests; merge conflicts are limited to appended lines.
- Runs on uncommitted code are marked `commit_dirty: true`, so the trend shows which numbers came from committed code.
- CI runs append only to the CI checkout, which is thrown away; only runs a human commits become part of the history.
- The file grows by roughly one line per run. That is acceptable at this scale; rotation is not needed in P5.
