# TrustRAG specification

Highest source of truth (see `CLAUDE.md` section 2). Change this file only with human approval.

## 1. Baseline: v1.0.0 (released, must not regress)

v1.0 behaviour is specified by its tests, `ARCHITECTURE.md`, `THREAT_MODEL.md` and ADRs 0001–0008. In short:

| ID | Requirement | Evidence |
|---|---|---|
| B1 | Answers use only retrieved document text and cite `[file, p.N]` for each fact | `src/generator.py`, eval citation accuracy |
| B2 | If the documents lack the answer, reply exactly `config.REFUSAL_TEXT` | `tests/test_security.py` #1 |
| B3 | Every non-refusal answer is fact-checked; SUPPORTED requires a verbatim quote | `src/verifier.py`, THREAT_MODEL #3 |
| B4 | Every chunk is scanned (rules + AI) before indexing; fail closed when AI is unavailable | ADR 0002, 0008 |
| B5 | Workspaces are isolated (128-bit ids); anonymous workspaces expire after 24 h | THREAT_MODEL #4 |
| B6 | Limits: 25 MB, 300 pages, 50 OCR pages, rate limits from settings | `src/settings.py` |
| B7 | HTTP API `/v1/workspaces…` contract as in `api/main.py`; optional `X-API-Key` | `tests/test_architecture.py` |
| B8 | Eval baseline: recall@4 100%, MRR 0.97, injection removal 100% / 0% false removal | `eval/results/RESULTS.md` |
| B9 | All 19 THREAT_MODEL mitigations keep their regression tests green | `tests/test_security.py` |

## 2. Roadmap phases

Phases continue numbering after v1.0 (P1–P4 ≈ v0.1–v1.0). Each phase below is **DRAFT** until `/architecture`
turns it into `docs/phases/pNN-plan.md` and the human approves it. Nothing outside the listed scope is built.

Order chosen by risk: cheapest and most reversible first, paid infrastructure last.

| Phase | Name | Status |
|---|---|---|
| P5 | Public benchmark evaluation + eval trend report | draft |
| P6 | User accounts and persistent workspaces | draft |
| P7 | Server-based storage (pgvector, Redis) for multi-host | draft |
| P8 | Cloud deployment with HTTPS and SSO | draft — blocked on human decisions |

### P5 — Public benchmark evaluation + eval trend report

Goal: show quality on data the author did not write (README "Known limitations": eval is self-authored).

Scope:
- Loader for one public document-QA dataset with a licence that allows this use (choice = SPEC-GAP-005).
- Run retrieval metrics (recall@k, MRR) offline on it; answer-level metrics only via `make eval` (human gate).
- Append every eval run to a history file; generate a static trend report (Markdown) from it.

Acceptance criteria:
- P5-AC1: `make eval-free` runs the public benchmark retrieval suite without network calls after download.
- P5-AC2: Results are stored with commit, prompt versions and models, like `eval/results/results.json`.
- P5-AC3: A trend report lists at least the last 10 runs per metric and is regenerated by one command.
- P5-AC4: Existing baseline metrics (B8) are unchanged.
- P5-AC5: README "Measured, not claimed" section shows the public-benchmark numbers with dataset name and licence.

### P6 — User accounts and persistent workspaces

Goal: users keep their documents across sessions without sharing a password.

Scope (method still open — SPEC-GAP-003):
- Account model, login, logout, per-user workspaces that survive browser refresh.
- Anonymous mode (current behaviour) stays available and unchanged.

Acceptance criteria:
- P6-AC1: A user can only list, query or delete their own workspaces (tested at service and API level).
- P6-AC2: Credentials are never stored or logged in plain text; login is rate-limited and timing-safe.
- P6-AC3: Anonymous mode keeps B5 behaviour.
- P6-AC4: THREAT_MODEL gains rows for account takeover, enumeration and session theft, each with a test.
- P6-AC5: Data retention for account workspaces follows SPEC-GAP-004.

### P7 — Server-based storage for multi-host

Goal: remove the single-host limit (ADRs 0003, 0005) without changing behaviour.

Scope:
- `VectorStore` implementation on pgvector; state backend on Redis; selected by settings.
- ChromaDB + SQLite remain the default; `docker compose` profile adds Postgres and Redis.

Acceptance criteria:
- P7-AC1: The same service and security test suites pass against both backends.
- P7-AC2: Rate limit is shared across two API containers (integration test).
- P7-AC3: Retrieval eval on pgvector is within 1 point of the ChromaDB baseline, or the difference is explained.
- P7-AC4: New ADRs supersede or amend 0003 and 0005.

### P8 — Cloud deployment with HTTPS and SSO

Goal: a deployable reference setup. Blocked until cloud provider, SSO provider and budget are decided
(SPEC-GAP-007, -008). Until then only provider-neutral artefacts may be produced.

Acceptance criteria (provisional):
- P8-AC1: HTTPS only; HTTP redirects; security headers set.
- P8-AC2: SSO login maps to P6 accounts.
- P8-AC3: Cloud config uses an API-key provider; `claude_code` provider is refused (ADR 0007).
- P8-AC4: Secrets come from the platform's secret store, never from the image or repo.
- P8-AC5: Deployment is reproducible from the repo plus documented manual steps; no step is done by Claude.
